# JCL (mainframe version of the job streams)

> **Not tested.** This environment has no z/OS, so these members have never
> been submitted. They are written to be correct IBM JCL/IDCAMS, but treat
> them as a starting point, not something proven.

| Member | What it does |
|---|---|
| `CBSETUP.jcl` | IDCAMS `DEFINE CLUSTER` for all 25 indexed files + IEFBR14 allocation of the 7 sequential files (generated by `tools/genjcl.py`) |
| `CBPGM.prc` | Catalogued procedure: runs one program through RUNPGM with every dataset DD |
| `EODJOB.jcl` | End of day: backup (REPRO), clearing, payments, SI, EOD, repo-linked loan reset, credit cards, gold revaluation, branch cash, recon, GL, SORT, MIS, SQL feed |
| `CICSFILE.jcl` | TRANLOG as an ESDS with an alternate index on the account number, for the CICS inquiry screen |
| `MONTHEND.jcl` | Month end: interest, charges, AML, TDS, recon, GL, CSV extract, SQL reports, GDG copy of TRANLOG |

Record sizes and key lengths in `CBSETUP.jcl` are the real copybook sizes,
measured with `cobc -tsymbols`; every key starts at offset 0.

Each step uses `COND=(4,LT)`: RC 4 (warnings such as returned cheques) lets
the job continue, RC 8+ skips every later step — the same rule as
`jobs/common.sh`.

## What would change on a real mainframe

* `SELECT ... ASSIGN TO 'data/ACCTMAST.DAT'` becomes `ASSIGN TO ACCTMAST`
  (the DD name), and indexed files need `ACCESS IS DYNAMIC` with VSAM file
  status handling (`'97'` after OPEN is fine, etc.).
* GDG bases `CBANK.BKUP.ACCTMAST` and `CBANK.HIST.TRANLOG` must be defined
  first (`DEFINE GDG ... LIMIT(7)`).
* The online menus (BANKMAIN) would be a CICS front end; the batch programs
  run as they are.
* SQLLOAD/SQLRPT would use the DB2 precompiler and `EXEC SQL CONNECT` would
  go away (the plan is bound to the subsystem).
